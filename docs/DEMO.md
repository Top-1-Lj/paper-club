# 三分钟演示：从一篇论文到一次共读讨论

本期推荐先展示新增的三篇真实论文，具体三分钟流程、核对说明和截图见 [真实论文演示](CURATED_IMPORT.md)。下面保留从零录入与双账号互动的原演示流程。

## 演示前准备

1. 按 README 安装依赖，执行 `migrate`、`seed_demo` 和 `import_papers`，启动本机服务。
2. 打开 `http://127.0.0.1:8000`，确认论文列表出现。准备终端用于最后的重启验证。
3. 准备普通窗口和隐私窗口，分别登录 `lin` 与 `chen`，初始密码均为 `PaperClub2026!`。如果修改过演示密码，使用修改后的密码。
4. 下面新录入的是明确标识的“功能演示条目”，用于演示保存、评论与导出，不把示例内容当成学术事实。

## 0:00–0:25：说明解决的问题

保持匿名访问论文库，展示标签、检索和已有卡片。

讲解：“纸间把论文条目、个人阅读理解和同学讨论连接起来。论文信息公开可查，每个人分别维护自己的阅读卡片和阅读状态。”

## 0:25–1:10：林同学录入并写卡片

1. 在普通窗口登录 `lin`。
2. 点击“添加论文”，填入：
   - 标题：`功能演示条目：我的第一篇共读论文`。
   - 作者：`演示作者甲; 演示作者乙`。
   - 年份：`2026`。
   - 摘要：`仅用于展示系统功能的样例，不对应真实研究结论。`。
   - 标签：`共读演示,科研入门`。
   - 论文链接：`https://example.org/paper-club-demo`（明确的示例地址）。
   - DOI 与代码链接留空，展示可选字段。
3. 保存后创建自己的阅读卡片，按六个字段简短填写，例如：
   - 研究问题：`【演示内容】怎样记录并交流一篇论文的阅读理解？`
   - 核心方法：`把阅读过程拆成结构化字段，并邀请同学交流。`
   - 主要结果：`这里只记录演示步骤，不声称真实实验结果。`
   - 局限：`本条目是功能演示，尚未进行研究或复现。`
   - 个人理解：`先复述问题，再提出能回到原文核查的问题。`
   - 待讨论问题：`哪些信息需要补充来源？`
4. 将阅读状态选择为“在读”。

## 1:10–1:45：陈同学参与讨论

1. 复制刚创建的卡片地址，在隐私窗口打开并登录 `chen`。
2. 展示陈同学能阅读和评论，但没有修改林同学卡片的入口。
3. 评论：`【演示评论】建议补上原文段落位置，下次共读一起核对。`
4. 回到论文详情，查看陈同学自己的阅读状态，说明状态按用户独立保存。

## 1:45–2:20：检索与导出

1. 在论文库搜索 `功能演示条目`，按 `共读演示` 标签筛选。
2. 进入卡片详情，下载 Markdown，打开后展示中文及结构化段落。
3. 进入论文详情，下载 BibTeX；确认缺少 DOI 时仍可导出。
4. 切换到“我的阅读卡片”，展示只筛选当前用户自己的卡片。

## 2:20–3:00：持久化与交付

1. 在终端按 `Ctrl+C` 停止服务。
2. 用 README 中的同一条 `runserver` 命令重新启动，保持同一个数据库路径。
3. 刷新刚才的论文/卡片页面，查看新条目、卡片和评论仍存在。
4. 展示 GitHub 所需的源码、数据库迁移、测试、依赖清单和 README。

讲解：“数据库独立保存在本机，重启后内容保留。仓库通过迁移与种子命令重建演示，后续可以接入社区统一登录和数据库。”

## 额外验收（可在三分钟讲解之外进行）

- 在另一账号下尝试访问卡片编辑地址，确认后端也拒绝跨用户修改。
- 尝试删除已经关联卡片的论文，确认提示删除保护。
- 连续两次执行 `seed_demo`，确认第二次不重复添加样例，不改已有密码或编辑内容。
- 搜索一个不存在的词，检查空状态；清除条件后回到完整列表。
- 验证长标题、中文及 `& % _ { }` 等特殊字符的导出。
- 输入不合法年份或网址，检查错误提示并确认未保存错误数据。

演示过程中的功能条目可以保留供复验。若需清理，按“评论 → 阅读卡片 → 论文”的关系顺序处理；有关联卡片时，论文删除保护是预期行为。
